# 75-second desktop demo

Preparation: run the app, use a desktop window, and keep extraction unconfigured.
All candidates and the sample role are fictional. Use search to find named profiles
quickly; clear it between steps. No live provider request is needed.

| Time | Action and narration |
| --- | --- |
| 0–10s | Click **Load fictional sample**. “This explains both employer requirements and candidate preferences. The baseline has8eligible,9blocked and8needing clarification.” |
| 10–25s | Search **candidate-02**, open **Explore Demo Birch**. Show employer/candidate work-mode failures and the exact marked **Work policy: office only.** quote. “This is a specific mutual policy conflict, not a low probability score.” Close details. |
| 25–40s | Open **Work mode** in the sidebar, leave **office** checked, add **remote**, click **Apply requirement**. “A scenario preserves the original baseline. Birch becomes eligible.” Clear search; show counts9eligible,8blocked,8clarification. |
| 40–52s | Search **candidate-15**, open **Demo Oak**. Show salary failures. “Remote resolves only the work-mode blocker. Salary still blocks this match in both directions.” Close. |
| 52–63s | Search **candidate-16**, open **Demo Pine**. Show unknown salary questions beside the explicit skill rejection. “Missing facts stay unknown; they are never silently treated as failure or hidden by another blocker.” Close. |
| 63–75s | Click **Reset scenario**, clear search; show baseline8/9/8 again. “Optional extraction creates a reviewable draft, never an automatic decision. This is an independent prototype using invented profiles, not affiliated with Clera.” |

For a longer walkthrough, demonstrate keyboard Escape/focus return or local reload
restoration. With configured credentials, extraction requires review and explicit
confirmation; live provider quality is not part of the recorded demo evidence.
