Document T09 contract: draft not persisted/applied automatically; unknown fields retained as null and reviewable warnings. Return safe placeholder title if absent, explicitly warning rather than pretending it was quoted.
2. Separate strict provider-output schema from final domain role. Provider emits typed supported claim values, exact quote and optional occurrence/offset hint, importance proposal/explicitness, and unsupported-field warnings; unknown values are null. Use bounded arrays/string lengths. Structured Outputs-compatible schema must be closed (`additionalProperties:false`) with required keys and nullable optional data. Root object; avoid unsupported JSON Schema refinements in provider schema. Independently validate returned structure with Zod and final role with existing roleSchema. Unknown extra provider fields are rejected/flagged, never silently turned into requirements.
3. Add pure grounding conversion. Locate exact quotes in unchanged source via UTF-16 indices; verify any supplied span. Missing or absent quote cannot ground a known fact. Repeated quote without valid disambiguation => null/omit claim with explicit warning, never arbitrarily pick first. Unknown facts have no evidence. Exact span equality alone is insufficient: verify conservative supported value/quote correspondence for skills, salary amounts/currency/annual base units, accepted modes, canonical locations, and dates. Reject/flag unrelated quote, unsupported normalization, negation or ambiguity rather than invent certainty. Unsupported salary units => unknown, not assumed USD/annual. Only explicit mandatory language can avoid an inferred-importance warning. Ambiguous values must not be silently defaulted to mandatory verified facts. Document limited semantic checks and mandatory human review; do not promise complete natural-language entailment validation.
4. Implement server-only provider adapter (`provider.ts` or equivalent) with `import "server-only"` at production boundary, injectable fetch/clock for tests, fixed official OpenAI Responses URL, API key read only server-side, required `OPENAI_API_KEY` and `OPENAI_MODEL` (explicit configurable model avoids claiming undocumented default). Use `store:false`, no tools, no raw input logging; structured output-only instruction plus separate untrusted user text. Never execute pasted instructions or let text alter endpoint/model/config. Parse completed text output; safely handle refusal, incomplete, malformed JSON, absent content and schema violations. Do not blindly use SDK-only `output_text` convenience against raw REST envelope.
5. Bounded policy: total 20-second request budget, each attempt capped at 10 seconds, at most one retry for eligible network/429/5xx transient failure only if budget remains. No retry for invalid output/refusal/auth/validation; bound retry delay within remaining budget and cap any Retry-After. Apply cancellation/timeout through body parsing too; caller abort stops work. Inject timers/fetch for fast deterministic tests; clean timers after all outcomes. Document policy constants; don't add an SDK whose own retry defaults multiply calls. Limit provider output/body size sufficiently for bounded parsing.
