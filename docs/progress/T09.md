## Plan and acceptance criteria

1. Add pure review/confirmation helpers under extraction (e.g. `review.ts`) using existing Role schema. Suggested API: `createReview(success)` returns detached draft plus edit metadata; `editReview(review, change)` validates typed title/value/importance/enabled changes; `confirmReview(currentRole, review)` returns validated `{ role, scenario }` with revision `currentRole.revision+1`, empty `createScenario(nextRole)`. Stable active role ID may be retained to represent revisions; document choice. Do not derive revision from draft's default1. Reject invalid draft, blank title, zero-weight active requirements, stale review identity/session, or invalid change atomically. Do not silently discard unknown requirements to get eligibility; retain null requirements/questions. Confirm with zero requirements only if UI clearly warns no requirements evaluated.
2. Track value and editorial edits separately. Value correction => manual fact and empty evidence; same-value no-op retains original extracted fact/quote. Importance/enabled edits do not alter quoted value provenance; visibly mark importance/enabled as recruiter-edited using per-constraint metadata. Title correction visibly marked manual. Keep original draft/source/warnings inspectable. Prefer conservative labels without domain/storage migration: show quoted evidence supports value only, and treat importance as recruiter-confirmed after confirmation (never imply its quoted support). If persistent fine-grained editorial metadata needed, extend envelope deliberately with validation/migration tests; do not attach false quotes or lose unknowns. New confirmed role's unchanged values keep exact evidence; manual changes cannot regain quotes unless explicit revert restores original draft.
3. Add accessible paste-and-extract area and review panel in dashboard. Explain text sent to server/provider before request; existing no-key sample remains usable. Textarea controlled, max20k with remaining/error feedback, empty/oversize prevent request. On submit POST JSON original text; validate success with `extractionSuccessSchema`. Pending status and cancel button; failure safe message with original text preserved; existing baseline, scenario, counts and saved data untouched. Avoid displaying raw server/provider failure payloads. Draft never automatically persisted or used by matching.
4. Guard request lifecycle with AbortController plus monotonic request ID/session generation. Cancel, new submission, input change while pending, discard, load sample, clear data and unmount invalidate older responses even if abort ignored. Bind draft to exact submitted text and review generation; prevent an older request/draft from replacing newer input or confirming against a changed baseline. Either freeze input while pending or invalidate request on editing explicitly. Confirm/cancel actions disabled while restoring/pending as applicable; notices announce state without stealing focus unnecessarily.
5. Review displays warnings, original source quotes/highlights, every supported typed field (skill/salary/modes/location/date), importance, enabled state, title, null values and manual-origin labels. Separate field draft state permits invalid edits without corrupting review; disable confirmation while any visible field remains invalid/unapplied. Corrections apply to review only; matching remains on old confirmed baseline/scenario until explicit Confirm role. Discard restores no application state because baseline never changed. Confirmation atomically swaps role+empty scenario, increments latest active revision, clears selected detail/editor drafts, persists new baseline and scenario once. Refactor dashboard role/scenario into a joint reducer/state object if necessary to guarantee consistent matching render; don't evaluate a new role against an old scenario during intermediate updates.
6. Confirmed role UI labels title/importance editorial confirmation truthfully and exposes manual value facts/evidence. Reset scenario returns to this new confirmed baseline, not original sample. Reload restores new role/revision/empty-or-current scenario; Load fictional sample explicitly restores fixture role. Keep extraction drafts and pasted input session-local, not automatically stored.
